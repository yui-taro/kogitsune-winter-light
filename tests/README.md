# テストと設計書の対応表

更新: 2026-10-07。最上位の方針は [検証・受け入れ計画書](../design/verification.md)、要件 ID は [要件定義](../design/requirements.md)、固定盤面と Jev 契約は [狛犬・Jev仕様](../design/komainu-jev.md) にある。

**自動テストの通過は、V0〜V6 の総合合格や公開品質を意味しない。** 自動テストが証明するのは、ゲーム状態・中継・C++ クライアントの確定的な契約だけ。Jev の判断品質、初見プレイ、画質・音、Windows 実機、速度・費用は、下の表で「手動」「実API」「実機」とした別の記録が必要になる。未測定の項目を合格と書かない。

## 実行方法

```sh
make -C game test build/test_bridge
cd server && node --test test.mjs
```

`server/test.mjs` の結合テストは `game/build/test_bridge` を使うため、先に C++ をビルドする。ループバックの空きポートを OS に割り当てさせるため、サンドボックス環境ではローカル通信の許可が必要になることがある。

| テスト | 実行場所 | CI |
| --- | --- | --- |
| `tests/test_world.cpp`（状態の不変条件・通し進行） | `make -C game test`、CTest `world_invariants` | `tests.yml`（Ubuntu・macOS）、`windows-build.yml` |
| `tests/test_contract.cpp`（設計契約・固定盤面） | `make -C game test`、CTest `design_contract` | `tests.yml`（Ubuntu・macOS）、`windows-build.yml` |
| `tests/test_bridge.cpp`（C++ クライアントの HTTP 結合） | `server/test.mjs` から起動 | `tests.yml`（Ubuntu・macOS） |
| `server/test.mjs`（中継の正規化・異常入力・模擬 Jev 障害） | `node --test` | `tests.yml`（Ubuntu・macOS） |

## 判定の区分

| 区分 | 意味 |
| --- | --- |
| **自動** | 自動テストが設計の条件を直接検査している |
| **一部自動** | 条件の一部だけを自動で検査。残りは右欄の方法で確認が必要 |
| **未実装** | 自動化できるが、まだテストもゲーム側の仕組みもない |
| **手動** | 人の評価、実画面、実機、実API、費用測定が必要。自動テストの対象外 |

## テストで見つかった設計との差

- **修正済み:** Jev が形式不正の JSON を返すと、中継がクライアントの入力誤り（400）として応答していた。上流の障害として 503 を返すよう `server/relay.mjs` を修正した。
- **未対応:** `server/relay.mjs` は `model: 'jev-latest'` を送る。仕様書は比較試験で固定したモデル版を使い、応答の `model` を記録するよう求めている。実API試験の前に固定版へ変える。
- **未対応:** 429/529 で中継は再試行せずに 503 を返す。仕様書の「待機を増やす再試行」はまだない。高速再試行をしないことだけはテスト済み。
- **未対応:** 巣で弟妹を見る観測（J-06 の前提）がゲームの観測の種類にない。結末が固定されていることは検査済み。
