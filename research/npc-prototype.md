# 毎秒判断する敵NPC: 最小試作仕様

## 1回の判断

ゲームは60fpsなど通常の頻度で動かし、Jevへの問い合わせはまず各NPC **1秒に最大1回**。状態が変わらない時は呼び出さない。複数NPCが同時に判断する時は質問をまとめる。Jevの返答を待つ間も前回の意図を続ける。

```text
ゲーム状態
  → 視界・物音・障害物・クールダウンをコードで計算
  → 合法な戦術候補を生成
  → Jevに短いstateとChoice質問を送る（サーバー経由）
  → 返った候補を検証して意図として採用
  → 移動・射撃・経路探索・衝突はゲーム側
```

初期候補は `patrol`、`investigate_noise`、`search_last_seen`、`chase`、`call_backup`、`retreat`。不可能な候補は事前に除き、候補が1つだけならJevを呼ばない。`state` にはNPCの性格、現在の警戒段階、プレイヤーの最終目撃、直近の音、仲間との距離、直近の失敗を**短い説明文**で含める。座標比較や残弾数の計算はコードで行い、モデルには「近い」「遮蔽物の向こう」など意味のある状態を渡す。[公式の既知の弱点](https://docs.typesafe.ai/model-jaggedness/jev-1.13)

例示する質問:

```json
{
  "state": {
    "guard": "慎重で、単独追跡を避ける警備員",
    "situation": "廊下で足音を聞いた。プレイヤーは見えていない。仲間は隣の部屋にいる。",
    "recent_result": "直前の調査では何も見つからなかった"
  },
  "model": "jev-1.13.0",
  "questions": {
    "next_intent": {
      "type": "choice",
      "instructions": "この警備員が次に取る、状況に合う戦術的意図を1つ選ぶ",
      "criteria": {
        "patrol": "持ち場の巡回を続ける",
        "investigate_noise": "聞こえた音の場所を安全に確認する",
        "call_backup": "仲間に確認を頼む"
      }
    }
  }
}
```

これはAPI形式の設計例であり、実際の応答や判断品質を示すものではない。日本語入力での動作は要計測。

## 失敗時の挙動

- タイムアウト・429・通信断: 前回の意図を維持し、必要ならローカルの簡単なルールに切り替える。ゲーム画面を止めない。
- 古い応答: 問い合わせ後に状況が大きく変わった場合は破棄する。各NPCに状態バージョンを持たせる。
- 同じ行動のループ: 行動後に状態が進まなかったことを記録し、候補から一時除外する。
- 危険・不可能な行動: `confidence` に関係なくコード側の合法性チェックで拒否する。
- APIキー: ブラウザに渡さず、サーバーの環境変数に置く。

## 検証するもの

1. 20〜30個の盤面状態を固定し、各状態の合法候補と期待する行動の範囲を記録する。
2. ルール版とJev版を同じシードでプレイし、プレイヤーにどちらが状況に合って面白いか比較してもらう。
3. `model`、`state` の版、候補、確率、選択、入力トークン、応答時間、タイムアウト、フォールバック数をログに残す。APIキーや不要な個人データはログに残さない。
4. NPC数1・3・10、更新間隔0.5秒・1秒・2秒を試し、判断の質・遅延・費用を比較する。公開上限や実測費用を超える設定は採用しない。

**合格の目安（企画上の仮設定）:** 不正な行動が0、遅延してもゲームが止まらない、プレイヤーがJev版の違いと楽しさを実感できる。数値のしきい値は初回計測後に設定する。
