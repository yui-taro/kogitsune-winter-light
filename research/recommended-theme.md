# 推奨テーマ: 仮面夜会の怪盗

## 一文で説明するゲーム

夜会に紛れた怪盗として、変装・偽の手掛かり・会話の選択肢・囮を使い、**NPCが互いに伝え合う情報を操作して**宝石を盗み出す短編ステルスゲーム。仮題は「仮面夜会の怪盗」。

この案は、普通の警備ステルス、検問での駆け引き、複数エージェントの生活シミュレーションを一つの明確な目的にまとめる企画上の仮説。[Heist One](https://github.com/AbdelStark/heist-one) はJevによる警備員の判断、[Last Exit](https://github.com/0x963d/last-exit) は嘘や証拠に対する検査官の行動、[Jev Town](https://github.com/NevaMind-AI/JevTown) は複数住民の行動選択を試している。組み合わせた時の面白さや品質は未検証。

## 見せたい「AIでそんなことができるのか」の瞬間

プレイヤーが客にわざと「別の部屋に怪盗がいる」と噂を流す。客は信じて報告するか、自分で確かめるかを選ぶ。報告を受けた警備員は現場を離れるか、客を疑って持ち場に残る。警備主任は受け取った情報と監視カメラの矛盾から、調査先と封鎖場所を選ぶ。結果として宝石への道が開くことも、退路が閉じることもある。

重要なのは**どのNPCが何を知っているか**をゲームが明示的に記録すること。NPCに全情報を与えると「見ていないのに知っている敵」になり、駆け引きが壊れる。プレイ中は視線、仕草、短い台詞、無線と警備配置で反応を見せ、クリア後に「誰から誰へ情報が渡り、なぜ警備が動いたか」を再生できるようにする。

## 1回のプレイループ

1. 会場を観察し、人物の役割・移動・警備の穴を見つける。
2. 変装、招待状、音の囮、噂の中から一つの工作を選ぶ。
3. NPCが自分の観測と聞いた情報を基に判断し、配置と疑念が変わる。
4. 生じた隙を利用して宝石を取り、脱出する。失敗時も脱出経路を変えて立て直せる。

## Jevとゲームコードの境界

| Jevに尋ねる短い判断 | ゲームコード・制作側の仕事 |
| --- | --- |
| 客: 報告する／確認する／無視する | 誰が何を見聞きしたか、記憶の更新 |
| 警備員: 持ち場を守る／調べる／応援を呼ぶ／尋問する | 視界、音、移動、経路、合法な行動候補 |
| 主任: 人員をどこに割くか、どの情報を疑うか | 警備人数、扉、時間、クリア・失敗条件 |
| 疑念の度合い、噂の信頼性の評価 | 台詞、演技、アニメーション、音、カメラ演出 |

Jevの[Choice・Score・Noul](https://docs.typesafe.ai/primitives) は短い状態から選択・評価を返す用途に合う。会話文や長期記憶を自動生成する仕組みではないため、台詞は収録・執筆した短文を状況で選び、知識と記憶はゲーム側で保持する。[既知の弱点](https://docs.typesafe.ai/model-jaggedness/jev-1.13) に合わせ、人数計算、時間、複数段階の計画はコードで扱う。複数質問を一度に送れる[fan-out](https://docs.typesafe.ai/patterns/fan-out) は、同じ状態を共有する判断に使う。NPCごとに見えている情報が異なる場合は、状態を分ける。

## 品質を支える構成

- 舞台は一夜の美術館夜会に絞り、照明・仮面・音楽・人混みを丁寧に作る。
- 目的と主要イベントは明確に設計する。Jevはその間の警戒、調査、相談、配置転換を変化させる。
- 判断が返るまで移動やアニメーションを止めない。期限切れ時は安全なローカル行動を選ぶ。[JevBall](https://github.com/atarikcaliskan/jevball) にも判断頻度の調整と代替行動の実装例がある。
- 「毎秒AI」は固定目標にせず、状況が変わったNPCと近くのNPCを中心に判断させる。実際の頻度は遅延と費用を測って決める。
- AI判断の偶然だけに頼らず、行動ごとの予兆と結果を分かりやすく描く。

## 最初の縦切り試作

展示室・廊下・宝石庫の3エリア、客1人・警備員1人・主任1人、工作は「偽の通報」と「音の囮」の2種類、盗んで出口に戻るまで5〜8分。まず同じ場面を固定ルール版とJev版で比較する。評価点は、プレイヤーがNPCの行動理由を説明できるか、工作の結果が攻略に影響するか、意外だが納得できる反応があるか、待ち時間や費用が許容範囲か。

現時点では企画提案。Jev APIでの実測、面白さのプレイテスト、完成品質はまだ確認していない。
