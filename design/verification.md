# 『こぎつねと冬の灯り』検証・受け入れ計画書

版: 0.3／2026-10-07  
状態: **レビュー用草案。試作・実API呼び出し・Windows実機評価は未実施。合否基準のうち対象機材や費用に依存する数値は測定前に確定する。**

## 1. 検証の目的と判定原則

検証するのは、子狐と灯籠の物語が初見で伝わること、狛犬のJev判断が手掛かりと性格に沿い攻略へ影響すること、絵本映画調の画面と運ばれる光が成立すること、Windowsで公開可能な形で動くこと。[要件定義](requirements.md)のE/F/A/P/G/N各IDを、[基本設計](basic-design.md)、[画面・操作仕様](ui-and-controls.md)、[狛犬・Jev仕様](komainu-jev.md)、[技術・素材設計](technical-and-assets.md)に沿って確かめる。

**判定は三つに分ける。** ①絶対に守る条件（観測外情報の利用、秘密鍵の混入、古い応答の実行など）は一例でも見つかれば不合格。②体験・画質は事前に決めた質問と観察方法で初見の人に評価してもらう。③速度・容量・費用は対象機材と配布方式を決めた後に数値目標を置き、実測値で判断する。未測定・対象未定を「合格」と書かない。

検証用の固定盤面・モックは公開版のJevを置き換えるものではない。完成版はプレイ中の接続を必要とし、短い障害だけローカル代替を使う（D-03）。制作人数・完成時期・日程はユーザーが管理するため、本書には入れない。

## 2. 記録と再現の共通形式

各試験で、試験ID、要件ID、場面・入力盤面、素材版、ゲーム版、モデル版・質問版、対象PC・画面サイズ、実施日時、操作・応答ログ、動画／画像、観察者の発言、合否と理由、修正後の再試験結果を残す。Jev試験では観測事実と真の盤面を**別々の欄**で保存し、外に漏れた情報を検出する。APIキー、個人情報、プレイヤーの自由文はログへ入れない。

| 記録 | 最低限含めること |
| --- | --- |
| `scenario` | 場面、狐・狛犬・灯籠・足跡・鈴の初期状態、観測可能範囲、期待する不変条件 |
| `run` | 入力操作、観測イベント、合法候補、Jev要求・応答、採用／破棄理由、ゲーム内時刻 |
| `media` | 通常画面サイズの静止画・短い動画・音声、必要なら白黒版と音なし版 |
| `decision` | 合格／修正／方式変更／未測定、理由、次に比較する版。主観評価は観察者の言葉を要約して残す |

比較試験では**同じ盤面・同じ地形・同じ入力順**で、ローカル固定規則版とJev版を走らせる。モデル版、候補、質問文、性格とそれに対応する行動傾向を同時に変えず、一度に一つの条件を変える。Jev応答の確率値は行動の抽選に使わず、性格・観測・記憶から選択を説明できるかを評価する（D-17）。

## 5. Jev固定盤面と障害注入

| 盤面ID | 狛犬が知ること | 検査する性質 |
| --- | --- | --- |
| J-01 鈴だけ | 灯籠を台座で最後に見た。鳥居の鈴を聞いた | 狐が鳴らしたと断定しない。守る／短く調べる／待つの合法候補だけ |
| J-02 足跡だけ | 新しい跡を右側で見た。鈴は聞いていない | 足跡の方向に注目し、まだ見ていない狐の座標を使わない |
| J-03 競合 | 右の足跡と左の鈴を知る | 両手掛かりを含む候補から一つ選ぶ。どの選択でも狐に対処の道が残る |
| J-04 空振り後 | J-03と同じ現在観測に、左の鈴を以前調べて空振りした記憶だけを加える | J-03との違いが記憶で説明可能。同一試行中は記憶が残る |
| J-05 盗難後 | 空の台座または運ばれる光を**実際に見た** | 観測後だけ出口警戒・光追跡などが候補になる |
| J-06 情の条件 | 巣で震える弟妹を実際に見た | Jevは結末の成否を選ばず、ゲームの確定演出へ移る |
| J-07 情報欠落 | 狐は木陰にいるが狛犬の視界外 | 送信状態と代替方針に狐の真位置が含まれない |
| J-08 障害 | 応答遅延中に盗難、429/529、形式不正、重複応答、CP復元 | 古い`attempt_id`・`revision`や候補外の意図が一度も適用されない |
| J-09 性格差 | 観測・記憶・合法候補を固定し、性格と対応する行動傾向だけ変える | 選択の差が性格の違いで説明できる。乱数や見えていない事実を理由にしない |
| J-10 同じ状態の再通知 | 性格・行動傾向・観測・記憶・合法候補を変えず、同じ通知を繰り返す | ゲームは新しい選択を求めず有効な意図を継続。手掛かりが変わった時だけ再判断する |
| J-11 CP復元 | S2で得た記憶を含むCP-Cを保存し、その後の空振りと盗難を経験してから捕獲される | S2の記憶は残り、CP-C保存後の空振り・盗難の観測は消える。灯籠は台座、狛犬の位置・姿も保存時点に戻り、旧試行の応答は破棄される |

各盤面でJevを複数回走らせる前に、固定するモデル版、候補説明、入力言語、性格・行動傾向の版、反復回数、期待する**禁止行動と許容行動**を記録する。生のJev応答は反復して揺れるか測り、性格や観測に反する選択があれば質問・候補・モデルを見直す。実際のゲームでは同じ状態の重複通知で新しい選択を求めない。[公式Choice仕様](https://docs.typesafe.ai/primitives/choice)の`probabilities`と`confidence`は返答に含まれても、抽選や正答率の判定に使わない。[公式API仕様](https://docs.typesafe.ai/api)にある`usage.input_tokens`を実測して費用を見積もる。

## 6. 初見プレイと美術評価の手順

**初期の形成的試験案:** 作品の設計を事前に知らない人を5人程度集める。ゲームの目的・四行動・狛犬の仕組みは説明せず、操作方法だけ必要最小限に示す。S0からS2の判断結果まで計時し、S3盗難、S4帰路、S5結末も進めてもらう。迷った箇所、最初に選んだ道、使わなかった行動、捕獲理由の理解、狛犬の意図への予想を記録する。5人は問題発見の初期規模であり、完成品質を統計的に証明する数ではない。

| 課題 | 評価する質問・観察 |
| --- | --- |
| 冒頭 | 「狐は誰のために、何をしようとしている？」を本人の言葉で聞く |
| 狛犬の初遭遇 | 予兆の途中で止め「次にどこへ行くと思う？」。結果を見た後「なぜそうしたと思う？」を聞く |
| 工作と帰路 | 鈴・足跡・尾で払う・灯籠を置く行動の意味と代償を説明できるか。二つの出口を見つけられるか |
| 捕獲後 | 何を見聞きされて捕まったと思うか、次は何を変えるかを聞き、ログと照合する |
| 結末 | 狛犬が巣に来た理由、弟妹を見てから火を分けた順番、神社に灯籠が戻ったことが伝わるか |

実画面静止画を1秒見せて子狐・狛犬・灯籠を指してもらう。白黒・無音の短い動画では伏せる／走る／足跡を消す／灯籠を運ぶの区別、鈴と狛犬の予兆を確認する。結果は「全員がそう感じた」の一文で済ませず、各人の回答と迷いを残す。最終的な人数と主観項目の通過割合は、テスト実施前に[要件 E-01〜05](requirements.md)の受け入れ条件として決め、試験後に都合よく変えない。

## 7. 遅延・費用・性能の測定

| 項目 | 記録する値 | 合格目標を置く条件 |
| --- | --- | --- |
| Jev応答 | 成功・失敗数、p50/p95、タイムアウト、期限切れ破棄、429/529、再試行数 | 対象地域・中継先・モデル・質問版を固定してから |
| 利用量と費用 | 呼び出し契機別件数、`usage.input_tokens`、1プレイの合計、公開時の単価での推計 | 理想の狛犬行動と試遊の実際の呼び出し数が出てから。予算上限はD-06として後で判断 |
| ゲーム性能 | 画面更新のフレーム時間、入力遅延、起動・場面切替、ピークRAM/VRAM | 対象Windows PCと最低画面サイズを決めてから |
| 素材工程 | 同じ設定の再書き出し、アトラス容量、欠損・ピボット・アルファ検査 | 描画方式と素材の採用版を決めてから |

Jevの公開単価・レート上限は変化し得るため、試算には計測日の[公式モデル一覧](https://docs.typesafe.ai/models)を使い、単価と計算式を記録する。**APIのメーカー公表値を自作ゲームの実測値として使わない。** 数値目標が必要なN-02・N-08・D-06は、機材と公開方式が決まるまで「未設定」とし、V4・V6の最終合格を保留する。

## 8. 公開前の判定と失敗時の戻り先

| 失敗 | まず直す文書・設計 | 再試験 |
| --- | --- | --- |
| 最初のJev見せ場が遅い | `story-and-levels.md`のS0・S1演出と導線、`ui-and-controls.md`の説明量 | 初見S0→S2を再計時 |
| 狛犬が理不尽・観測外情報を使う | `komainu-jev.md`の観測・記憶・候補、地形の視界判定 | J-01〜08と実プレイを再実行 |
| 灯籠の光が不自然 | `technical-and-assets.md`の合成、遮蔽物、照明の出力 | V3動画を同じカメラで比較。必要なら3D方式を試す |
| 捕獲とCPが重い／矛盾する | `basic-design.md`と`story-and-levels.md`のCP、記憶、帰路の距離 | 盗難前・後・S4後半の失敗から再試遊 |
| 遅延・費用が合わない | `komainu-jev.md`の契機、候補・状態の長さ、中継方針 | V4を同じ盤面と対象回線で再測定 |
| Windows配布が成立しない | `technical-and-assets.md`と`release-and-operations.md` | 対象実機のクリーンインストールからV6再実行 |

**公開判定:** 必須の要件に対応するV0〜V6の結果と証拠、対象Windows、接続先、単価・費用、素材権利の台帳がそろって初めて公開可とする。追加候補（A-06、G-04、P-06など）は採否を記録し、未採用なら必須ゲートを妨げない。受け入れに必要な数値が未設定なら「合格」ではなく「判断保留」と記録する。
