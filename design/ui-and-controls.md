# 『こぎつねと冬の灯り』画面・操作仕様書

版: 0.2／2026-10-05  
状態: **レビュー用草案。キー割当・表示条件・操作結果は実装と試遊のための設計提案。ユーザー決定済み事項、任意要素、未決定事項を区別する。**

## 1. 対象と基本規則

本書は[基本設計書](basic-design.md)の各画面を操作できる形へ落とす。世界のルールは[ゲーム設計書](game-design.md)、場面の流れは[物語・レベル設計書](story-and-levels.md)、見た目と音の基準は[美術・音・画面方針書](art-and-audio.md)に従う。

- **決定済み:** 主な対象はWindows PC、初版の入力はキーボードとマウス。狐ができる行動ボタンをプレイ画面の右下に常時表示する（D-02、D-07、P-02）。ボタンは使用不可になっても移動・消去しない。
- **本書の提案:** 2×2の四行動、以下のキー割当、行動モードの切替、対象選択と表示文、ポーズ・再挑戦の操作、短い近景のスキップ方法。
- **未決定:** 完成版の解像度・最小ウィンドウ、キー変更機能、ゲームパッド対応、近景演出そのものの採否、アプリ終了後の再開、長時間通信断の復元方法。ゲームパッドは初版の前提にしない。

原則は**押す前に結果が予測できること**。行動できない時はボタンを残し、理由を短く示す。鈴、足跡、灯籠、狛犬の予兆には、色以外の形・動き・文字・音から少なくとも二つの手掛かりを用意する（N-05）。通信やJevの確率はプレイ画面に表示しない。

## 2. 入力割当と入力の優先順位

| 入力 | プレイ中の結果 | 他の画面での結果 |
| --- | --- | --- |
| `W` `A` `S` `D` | 狐を画面に対応する四方向へ移動。複数キーは斜め移動 | メニューでは矢印キーと同じく選択肢を移動する案 |
| `Ctrl` | 「伏せる」を切り替える。再度押すと歩行姿勢へ | 操作なし |
| `Shift` | 「走る」を切り替える。再度押すと歩行へ | 操作なし |
| `Q` | 現在位置の近くで尾で足跡を払う。押すたびに一回要求 | 操作なし |
| `E` | 選択中の対象に触れる／灯籠を置く。押すたびに一回要求 | 操作なし |
| `Tab` | 届く範囲に複数の「触れる」対象がある時、次の対象へ切り替える | 操作なし |
| `Esc` | ポーズを開く。演出中は演出用ポーズを開く | ポーズ・説明は元の画面へ戻る。接続確認・障害画面は戻れる選択肢へ移る |
| `Enter`・`Space` | 通常プレイでは操作なし | 選択中のメニュー項目を決定。近景演出では画面に表示されたスキップ操作を行う案 |
| マウス左クリック | 右下の行動ボタンを押す／画面内の届く対象を選択する | メニュー項目を決定 |

**入力の優先順位:** モーダル画面（ポーズ、説明、捕獲、通信障害）が開いている間はゲーム内の移動・行動入力を受け付けない。近景演出中はポーズと、採用したスキップ入力だけを受け付ける。HUD上のクリックは世界内の対象選択へ通さない。ウィンドウが非アクティブになった時はゲームを自動ポーズする案とし、キーが押されたままの状態を解除する。

**四行動の排他:** 「伏せる」と「走る」は同時に有効にしない。片方をオンにした時はもう片方をオフにする。移動キーを放しても現在の姿勢・移動モードは保ち、HUDに明示する。捕獲、チェックポイント復元、演出開始時はモードを安全な歩行へ戻す。灯籠をくわえて走ることは可能な案だが速度は制限される。具体的な速度・音量は試遊で決める。

マウスの四ボタンは対応するキーと**同じ操作要求**を送る。押下が無効だった場合に、キーボードだけが成功したり、クリックだけが世界状態を変えたりしない。キー変更機能を採用する場合は、ボタン内のキー表記も変更結果に追従させる。

## 3. 通常プレイ画面とHUD

```text
┌──────────────────────── プレイ画面 ────────────────────────┐
│ 目標（短文）                            ポーズの入口         │
│                                                           │
│     子狐       足跡              狛犬         灯籠          │
│           [対象の印・対象名]                               │
│                                                           │
│                                     ┌────────┬────────┐     │
│                                     │伏せる   │走る     │     │
│                                     ├────────┼────────┤     │
│                                     │尾で払う │触れる   │     │
│                                     └────────┴────────┘     │
└───────────────────────────────────────────────────────────┘
```

四ボタンの位置と並びは固定。各ボタンに**アイコン、短い文字、割当キー**を載せる。木彫りのお守り風の輪郭を使い、背景を大きな不透明パネルで覆わない。[美術方針](art-and-audio.md)にある優先順位に従い、子狐・狛犬・灯籠の判読をHUDより優先する。S2の観察点とS3の台座では、重要な物が右下のボタンの下へ入らない構図にする。

| ボタン状態 | 表示 | 操作した結果 |
| --- | --- | --- |
| 使用可 | 明るい縁、通常の文字・アイコン。`Ctrl`／`Shift`のモードがオンなら押下形と小さな「使用中」印を加える | 対応する要求をゲームに渡す |
| 使用不可 | 同じ位置で灰色と斜線。短い理由をボタン横または近くの説明欄に出す | 状態を変えない。無効である軽い反応だけ返す |
| 対象あり | 「触れる」の位置は固定し、内側の文言と補助アイコンを「鳴らす／くわえる／置く／寄せる」に変える | 対象名を確認してから操作する |
| 演出中 | 同じ位置に薄く残し、操作不可の印を出す | 操作しない。操作可能になった瞬間に通常表示へ戻す |

**画面の共通領域:** 目的は短い一文で必要な時だけ表示し、常時読ませ続けない。対象の印は対象物のそばに置き、狐の近くには選択中の対象名を短く表示する。足跡や鈴が世界内で十分読めるなら、追加の大きな説明パネルは出さない。吹雪、影、近景でもボタンの文字と対象名のコントラストを保つ。1920×1080は評価用で、16:10と小さめのウィンドウでも同じ配置を確認する（完成版の対応解像度は未決定）。

## 4. 四行動の表示条件と操作結果

| 行動 | 使用できる時 | 使用できない時の例・表示 | 成功時の結果とフィードバック |
| --- | --- | --- | --- |
| 伏せる | 狐を操作でき、姿勢を変えられる時 | 捕獲・近景中は「いまは操作できない」。地形上で姿勢変更が不可能な場合は「ここでは伏せられない」 | 低い姿勢に切替。速度と足音が下がり、倒木の下を通れる。足跡は残る。HUDに「使用中」印 |
| 走る | 狐を操作でき、走行可能な地形にいる時 | 低い倒木の中などでは「ここでは走れない」 | 速度が上がり足音と足跡が目立つ。灯籠運搬中は速度制限。HUDに「使用中」印 |
| 尾で払う | 近くに消せる新しい足跡があり、尾の動作を行える時。灯籠運搬中も可 | 跡がなければ「払う足跡がない」、遠い跡のみなら「足跡に近づこう」 | 狐が短く留まり尾で近くの跡をならす。雪の舞いと柔らかい音で消えた範囲を示す。狛犬が既に得た記憶は消えない |
| 触れる | 選択中の合法な対象が届く範囲にある時、または安全に灯籠を置ける時 | 対象なしなら「近くに触れる物がない」、距離不足なら「もう少し近づこう」、置けない地面なら「ここには置けない」 | 対象に応じて小枝を寄せる、鈴を鳴らす、灯籠をくわえる／置く。実行結果に合わせて音・動き・HUD文言を更新 |

狐の姿勢・運搬状態・周囲の地形が変わったら、使用可否を同じ更新の中で再判定する。ボタンが有効に見えた直後に状態が変わり実行できなくなった場合は、何も起きないまま放置せず、上表の理由を返す。行動が成立したかどうかは世界状態が決め、HUDはその結果を表示する。

**伏せる・走るの誤解を避ける:** 伏せても透明にはならず、開けた場所では見つかる。走ると直ちに見つかるのではなく、狛犬が実際に聞く・見る条件を満たした時に手掛かりになる。現在の姿勢と運搬状態が画面上の狐の動きでも分かるようにする。

## 5. 「触れる」の対象選択

1. ゲームは狐から届く範囲にある物のうち、現在の状態で操作可能な対象だけを候補にする。画面上の近さだけで、壁や遮蔽物の向こうの物を選ばない。
2. 候補が一つならその物へ小さな印と名前を出す。複数なら、狐との地面上の距離が近い順に一つを初期選択し、同距離では固定した物ID順を使う。`Tab`か対象へのクリックで明示的に切り替えられる。
3. `E`またはHUDの「触れる」は**表示中の対象だけ**に作用する。押した瞬間に候補が消えた場合は実行せず、理由を表示する。選択変更だけでは鈴を鳴らしたり灯籠を取ったりしない。
4. 灯籠をくわえている時は「置く」を優先する。他の口を使う対象は無効表示にし、誤って鈴を鳴らさない。地面に安全な置き場所がない時は「置く」を無効にする。S5の巣では指定位置への「置く」だけを有効にする。

| 場面・対象 | 「触れる」の文言 | 押した後 |
| --- | --- | --- |
| S0の小枝 | 寄せる | 小枝が寄るが火はつかない。神社の灯りを見上げる場面へ進む |
| S2の鈴 | 鳴らす | 鈴が揺れ、音と雪落ちが起こる。狛犬が聞いた時だけ観測に入る |
| S3の台座の灯籠 | くわえる | 灯籠は狐の所持になり、台座が暗くなる。盗難演出へ進む |
| 灯籠を運搬中 | 置く | 狐の届く地面へ置く。灯籠の光はその場に残り、狐は身軽になる |
| S5の弟妹のそば | 置く | 灯籠が巣の小枝のそばに置かれ、確定した結末演出へ進む |

灯籠がすでに台座から離れて地面にある時も、届く範囲で再び「くわえる」を表示する。狛犬が回収したら灯籠は台座へ戻り、再取得には神社へ戻る必要がある。物語上の結果を変える操作には、押す前に対象名と動詞の両方が見えることを必須にする。

## 6. 場面ごとの案内と操作可能範囲

| 場面 | 最初に見せる案内 | 操作・HUD | 場面を離れる条件 |
| --- | --- | --- | --- |
| S0 巣 | 小枝へ印を出し「E 寄せる」。灯りを見上げた後に「灯りを持って帰ろう」 | 冒頭の非操作演出中も四ボタンは同じ位置に薄く表示。操作開始で通常表示。移動と「触れる」を学ぶ | 巣の出口からS1へ |
| S1 森・高台 | 最初の雪に足跡が出た時だけ「跡が残る」を短く示す。倒木・開けた道・消せる跡で行動を順に示す | 四ボタンは常設。狛犬の遠景は演出で、ここでは追跡されない | 森の出口からS2へ |
| S2 鳥居・鈴 | 観察点で風の鈴と狛犬の反応を見せる。狛犬が石のまま残る場合も耳と視線の予兆を見せる | プレイヤーが追加で鈴を鳴らし、足跡を残す／払う、二つの出入口を選べる。HUDが狛犬の選択を先取りしない | 鳥居または倒木の抜け道からS3へ |
| S3 境内 | 灯籠に近づいた時「くわえる」を示す | S2の狛犬の位置・姿・記憶を保持。盗難演出中もHUDの場所を維持 | 灯籠を持ち神社エリアを出るとS4 |
| S4 帰路 | 灯籠の光が雪と狐を照らす。必要なら一度だけ「置けば身軽になる」を短く示す | 運搬中も尾で払える。置いた灯籠は再取得できる | 灯籠を持って巣へ入るとS5。灯籠が台座へ戻れば神社へ再訪可 |
| S5 巣・結末 | 弟妹のそばに置く対象印を出す | 最初の「置く」だけ操作可。その後の四ボタンは薄く残す | 結末後、エンディングへ |

S2・S3の神社エリア共有と社前の台座（D-15）、鳥居と倒木の二つの出入口（D-16）は決定済み。実画面での見え方は[基本設計](basic-design.md)とあわせて検証する。S0・S1の説明を増やす時も、最初のJev判断と結果へ初見の通常進行で10分以内に到達する条件を守る（P-07）。

## 7. 狛犬の予兆・危険・失敗表示

| 事実・段階 | プレイヤーが見る／聞くもの | HUDでの扱い |
| --- | --- | --- |
| 鈴が鳴った | 鈴の揺れ、雪落ち、音。音なしでも鳴ったことが分かる | 必要なら鈴の位置に短い印。狛犬が聞いたかは、狛犬の耳や姿勢の反応で示す |
| 新しい足跡／払った跡 | 深い跡と雪音／尾の動きと雪の舞い。古い跡は輪郭が薄い | 常時の矢印や詳細数値は置かない |
| 狛犬が注目先を選ぶ | 石像なら耳と目線、山犬なら首・体の向き。持ち場を離れる時は雪落ちと前足の踏み出しを順に見せる | 意図名やJevの確率は表示しない。画面外でも実際に聞こえる狛犬の足音には控えめな方向印を併用する案 |
| 狐を見つけた | 狛犬の目線が狐に合い、身構え、足音が変わる。「気づく→向く→追う」の段階を見せる | 発見時だけ短い危険印。捕獲前に隠れる・道を変える余地を残す |
| 灯籠の盗難に気づいた | 狛犬が空の台座か光を実際に見た後に止まり、注目先を見る | 盗んだ瞬間に「見つかった」と自動表示しない |
| 捕獲成立 | 狛犬が狐を傷つけず確保し、場面を短く暗転 | 実際の観測に基づく一つの理由を示す。CP-BまたはCP-Cへの再挑戦操作を表示 |

画面外の方向印も、**プレイヤーが聞ける音など実際に提示された手掛かり**に限定する。狛犬が見聞きしたが狐には分からない内部記憶、巣の位置、Jevの選択肢は表示しない。視界の円錐を常時描く案は初版の標準表示にはせず、演技で分からない場合の試遊上の代替案として残す。

捕獲理由の文は「姿を見られた」「足跡をたどられた」「灯籠の光を見られた」「鈴の音に気づかれた」など、判断記録と一致するものから選ぶ。鈴を鳴らしただけで、その後に狛犬が狐を見たなら、直接の捕獲原因と鈴のきっかけを混同しない。狛犬が証拠を得ていない失敗理由を表示しない（A-01、F-05）。

## 8. メニュー・演出・通信画面

| 画面・状態 | 表示するもの | 操作と結果 |
| --- | --- | --- |
| タイトル | 新規プレイ、操作説明、終了。「続きから」はアプリ終了後の保存を採用した時だけ出す | 矢印キーまたは`WASD`と`Enter`、マウスで選択。新規プレイは接続確認へ |
| 接続確認 | 「接続を確認中」。失敗時は「接続が必要です」と再試行・タイトルへ戻る | 接続可ならS0または採用済みの保存地点へ。確認中は重複開始しない |
| ポーズ | 再開、操作説明、タイトルへ戻る | 世界とタイマーを止める。保留中のJev応答は再開時に鮮度確認。タイトルへ戻る前は必要なら現在の未保存進行が失われることを示す |
| 操作説明 | 移動、四行動、`Tab`での対象切替、足跡・鈴・光、ポーズの操作一覧 | タイトルから開いた時はタイトルへ、ポーズから開いた時はポーズへ戻る |
| 捕獲・再挑戦 | 捕獲原因、戻るCPの場所、「再挑戦」 | `Enter`またはクリックで世界をCPへ復元。古いJev応答は破棄する。タイトルへ戻る導線も置く |
| 短い通信障害 | 操作・描画は継続。必要なら「通信が不安定」を小さく表示 | 狛犬のローカル代替方針と予兆を維持。操作を遮らない |
| 長い通信障害 | 「接続が必要です」、再試行、タイトルへ戻る。安全地点で中断する案 | 再試行は現在の状態から接続を確認。安全地点・CPへの復元条件と発動閾値はD-09として未決定 |
| S0・S2・S3・S5の近景 | 表情と質感、短い必要情報。採用した近景だけ表示 | 採用する場合、`Space`長押しでスキップ可能とする案。スキップ後も灯籠・狛犬・進行の確定結果は同じにする |
| エンディング | 夜明けの構図、タイトルへ戻る操作 | 一つの結末のみ。プレイ後の「狛犬の記録」は追加候補として別途採否を決める |

**近景のスキップ:** 観測・盗難・結末の確定状態を、映像の再生位置で変えない。たとえばS3の盗難近景を飛ばしても、灯籠は狐の所持、台座は暗いままになる。S2で狛犬の予兆そのものを飛ばして危険だけ残すことは避け、スキップ後に通常画面で向きと姿勢を読める状態から操作を戻す。具体的な演出長とスキップ操作の最終採否は試遊で確認する。

## 9. 視認性・操作性の確認

| 確認場面 | 合否を見る観点 |
| --- | --- |
| 1920×1080、16:10、小さめのウィンドウ | 右下の四ボタンが同じ順で読め、狐・狛犬・灯籠・対象印を隠さない。完成版の対応サイズと文字寸法は`technical-and-assets.md`で確定 |
| 白黒表示・音なし | 使用可否、鈴、足跡の新旧、狛犬の予兆、捕獲理由が形・動き・文字で分かる |
| キーボードだけ／マウス併用 | 四行動、対象切替、ポーズ、再挑戦、接続再試行を完了でき、意図しない灯籠取得や鈴操作がない |
| 初見のS0〜S2 | 説明を読み続けずに四行動を覚え、開始から10分以内に狛犬の最初のJev判断と結果を見られる |
| 狛犬の三候補と盗難後 | 「守る／鈴を調べる／足跡を追う」の予兆、光を見た後の反応、隠れる・別道へ行く対処が読める |
| 捕獲・再挑戦・通信遅延 | 失敗理由とCPが分かり、再挑戦で状態が矛盾しない。短い遅延で入力が止まらず、古い判断が突然実行されない |

人数、評価用PC、時間・文字寸法・遅延の数値基準は`verification.md`で定める。本書の操作案は実画面と試遊で修正する。

## 10. 残る判断

1. `Ctrl`・`Shift`の切替式が、キーボード・マウス併用で誤操作を起こさないか。必要なら長押し式や設定での切替を試す。
2. 対象が重なる時の`Tab`切替と画面内クリックが、灯籠や鈴を誤って操作しないか。
3. 視界の常時表示なしで狛犬の注目先が読めるか。足りない時だけ補助表示を検討する。
4. 近景演出とスキップ、アプリ終了後の続きから再開、長時間通信断の安全な中断地点の採否。
5. 対応する画面サイズ、キー変更機能、ゲームパッド対応の範囲。
