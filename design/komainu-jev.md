# 『こぎつねと冬の灯り』狛犬・Jev仕様書

版: 0.3／2026-10-07  
状態: **レビュー用草案。判断の役割分担と確率抽選をしない方針はD-17で決定。Jev APIとの接続・判断品質・遅延・費用は未実測。**

## 1. 役割と守る条件

狛犬は灯籠を守る役目に忠実で慎重、幼い動物には情がある（A-02）。定位置では石の狛犬として観測し、持ち場を離れる意図を選んだ時に山犬へ変わる。同じ一体が位置と記憶を引き継ぎ、役目が落ち着いて定位置へ戻った時に石になる（D-14）。

Jevが決めるのは**性格から定めた行動傾向と、実際に得た事実・記憶に合う、次に優先する行動意図一つ**。確率値で候補を抽選しない。ゲームが視界・聴覚・足跡・灯籠の実状態、合法候補、移動・経路、捕獲、場面進行を確定する（D-17、A-01、A-03）。巣で弟妹を見た後の火を分ける結末はゲームが確定し、Jevに分岐させない（D-10）。[基本設計](basic-design.md)、[ゲーム設計](game-design.md)、[物語・レベル設計](story-and-levels.md)との境界を本書の契約とする。

**公平性の不変条件:** 狛犬が見聞きしていない狐の現在地・空の台座・巣の事情を、Jevの入力、ローカル代替方針、捕獲理由に使わない。見えていた狐が隠れた後は「最後に見た場所」だけを使う。足跡を後で消しても、一度見た記憶はその試行中に残る。ゲーム内の真実はサーバーへそのまま転送しない。

## 2. 情報モデル

| 層 | 保持する内容 | Jevへ送るか |
| --- | --- | --- |
| `GroundTruth` | 狐・灯籠・狛犬の真の位置、地形、足跡、音、遮蔽、吹雪、場面進行 | **送らない**。感覚判定と合法候補作成だけに使う |
| `Observation` | 狛犬が今見た／聞いた事実。種類、場所、ゲーム内時刻、感覚（視覚／聴覚）、観測元ID | その判断に関係する事実だけ送る |
| `Memory` | 最後に見た狐・光・足跡、聞いた鈴、調査済み地点、実際に空振りした地点。各項目に由来と古さ | 関連部分だけ送る。推測は観測事実と区別する |
| `Personality` | 任務への忠実さ、慎重さ、幼い動物への情。具体的な強さは設計案 | 採用した性格定義を毎回同じように送る。経験で書き換えない |
| `BehaviorTraits` | 性格を選択の基準にした行動傾向。例: 灯籠を守る、未確認の音は慎重に扱う、幼い動物への情は目撃後に示す | 性格の定義から固定して毎回送る。乱数で生成せず、観測・記憶と混ぜない |
| `LegalIntents` | 現在の姿・場所・既知の目標からゲームが許す少数の意図 | 候補IDと明確な説明を送る |

**観測の成立:** 視覚はゲーム内の視野・遮蔽・距離・照明から、聴覚は音源・距離・遮蔽から判定する。具体的な距離や吹雪の減衰値は境内1画面の試遊で決める。鈴を聞いた事実は「その場所で鈴の音がした」であり「狐が鳴らした」ではない。空の台座を知るのは台座を実際に見た時、灯籠の運搬を知るのは光や狐を実際に見た時。S1遠景の狛犬は演出で狐を観測しない。

**記憶の更新:** 新しい観測を追記し、同じ対象の最後の確認時刻を更新する。調査先で狐・灯籠を発見できなかった時は「空振り」を記録するが、狐がその場所に一度もいなかったと断定しない。古い足跡と新しい足跡を区別する値はゲームが計算し、Jevには狛犬が確認できた古さの区分だけ渡す。観測と推測を一つの自由文に混ぜない。

**性格から行動への対応（具体例は検証対象）:** 任務への忠実さは、鈴の音だけで灯籠から離れない傾向として表す。慎重さは、新しい足跡を実際に見た時や同じ鈴を調べて空振りした後の対応に表す。幼い動物への情は、弟妹を実際に見た後の演技と確定した結末に表し、未観測の事情を先取りしない。これらは固定した性格の**行動基準**であり、毎回ランダムに強弱を決める値ではない。複数の手掛かりが競合した時の具体的な優先順位は固定盤面で検証してから調整する。

## 3. 判断を求める出来事

| 出来事 | Jev判断の契機 | 判断を求めない条件 |
| --- | --- | --- |
| 風または狐による鈴 | 狛犬が鈴を聞いた時。S2の風の鈴は最初の共通契機 | 聞こえない距離・遮蔽、同じ音イベントの重複通知 |
| 足跡の発見 | 狛犬が新しい跡を視認・調査した時 | 狐が跡を作っただけで狛犬は未発見 |
| 狐の視認・見失い | 見た時と、遮蔽で見えなくなった時 | 画面に狐がいるだけで狛犬の視野に入っていない |
| 灯籠の盗難の証拠 | 空の台座、運ばれる光、狐の所持を狛犬が確認した時 | 狐が灯籠をくわえた瞬間を狛犬が見聞きしていない |
| 調査結果 | 目標地点で発見／空振りした時 | まだ到着しておらず、新しい事実もない |
| 結末 | 弟妹を実際に見た時にゲームの確定演出へ移る | 結末を選ばせるJev呼び出しはしない |

同じ盤面を毎秒問い合わせる方式は初版の通常動作にしない。D-17により、上表の**意味のある変化時**に判断する。短時間に複数の観測が重なった時は同じ更新単位でまとめ、古い決定を先に適用しない。まとめる時間幅、遅延、利用量は[検証計画](verification.md)で測る（A-07）。

## 4. 合法な行動意図と実行

| 意図ID | 内容 | 合法になる条件（提案） | ゲーム側の実行・予兆 |
| --- | --- | --- | --- |
| `guard_lantern` | 定位置で灯籠を守りながら観察 | 灯籠が台座にあると狛犬が知り、定位置にいる／戻れる | 石のまま耳と目線を鈴・灯籠へ動かす。戻る途中なら帰還して石へ |
| `inspect_bell` | 聞いた鈴の地点を調べる | 音の場所を知り、到達可能で、より新しい必須の追跡と矛盾しない | 行き先を見て、持ち場を離れるなら山犬へ変化して歩く |
| `inspect_tracks` | 実際に見た足跡の先を調べる | 狛犬が跡と方向を確認済み、到達可能 | 跡へ耳・視線を向けて歩く。消えた先の狐の真位置は使わない |
| `inspect_last_seen` | 狐または光を最後に見た地点を調べる | 最後の目撃点がある | 見失った方向を向き、地点まで移動。そこで再観測する |
| `watch_exit` | 既知の出入口の一つを警戒 | 盗難や侵入の証拠を知り、その出口へ到達可能 | 出口側へ向く／移動する。両出口を同時に封鎖しない |
| `follow_visible_clue` | 現在見える狐または灯籠の光を追う | 対象を今見ている。視線が切れたら再判断へ | 身構え→追う。捕獲の距離・遮蔽はゲームが判定 |
| `wait_and_watch` | その場で次の手掛かりを待つ | 少なくとも一つの安全な待機位置がある | 石なら耳・視線で「考えて残った」と示す。無理由の硬直にしない |

候補は**今できるものだけ**を各判断で作る。候補を一つにできない不確かな時でも`wait_and_watch`などの安全な候補を含める。ただし、盗難を知らない狛犬に空の台座を前提とする候補説明は渡さない。`watch_exit`の対象出口、足跡や鈴の対象地点はゲームが既知の到達可能地点から選び、Jevは任意の座標を新規生成しない。狛犬がどの合法候補を選んでも、狐には二つの出口・遮蔽・灯籠を置く行動など少なくとも一つの対処か、理解できる再挑戦が残る（[ゲーム設計6章](game-design.md)）。

**同じ一体の状態遷移:** `stone_at_post → awakening → animal_moving → animal_returning → stone_at_post`。持ち場を離れる意図が確定した時だけ`awakening`を始める。鈴が鳴っただけでは変化しない。移動中の再判断で突然石にならず、石化は定位置に戻った後。各遷移は耳・視線、雪落ち、前足の順に予兆を見せ、操作可能な狐が反応する時間を持つ。具体的な演出時間は試遊で決める。

## 5. 判断要求と応答の契約

### ゲームから中継先への概念契約

| フィールド | 内容 |
| --- | --- |
| `attempt_id` | 新規プレイ／CP再挑戦ごとに変わるID。前の試行の応答を混ぜない |
| `decision_id`・`revision` | 判断要求の一意IDと、その狛犬の判断に関係する状態改訂番号 |
| `npc_id`・`scene_id` | 一体の狛犬と現在場面の識別子 |
| `observations`・`memory`・`personality`・`behavior_traits` | 観測済み情報と、固定した性格・行動傾向を別々に保持。個人情報や狛犬が知らないゲーム内の真実を含めない |
| `legal_intents` | 候補IDと対象の既知地点、相互に区別できる説明 |
| `max_wait_ms` | プレイに間に合う判断の待機予算。値は実測後に決める |

中継先はJevの認証情報を保持し、上記をJevの`state`、`questions.next_intent`のChoiceへ変換する。Jevの[公式API](https://docs.typesafe.ai/api)は`state`、`model`、`questions`を送り、Choiceは`choice`、全候補の`probabilities`、`confidence`を返す。[Choiceの仕様](https://docs.typesafe.ai/primitives/choice)。ゲームが受け取るのは選ばれた`choice`であり、**`probabilities`から抽選・再抽選しない**。本書のゲーム・中継契約は**独自の概念契約**であり、Jev APIのJSONと同一ではない。

```json
{
  "model": "jev-1.13.0",
  "state": {
    "personality": {"duty": "high", "caution": "high", "mercy_for_cubs": "high"},
    "behavior_traits": ["protect_lantern", "verify_unconfirmed_clues", "show_mercy_after_observation"],
    "observed": [{"kind": "bell_heard", "place": "torii", "source": "hearing", "age": "just_now"}],
    "memory": [{"kind": "false_alarm", "place": "torii", "source": "searched", "age": "earlier"}],
    "known_lantern": "last_seen_on_pedestal"
  },
  "questions": {
    "next_intent": {
      "type": "choice",
      "instructions": "この守り手の固定した性格・行動傾向と、実際に観測した事実・記憶に最も合う行動を一つ選ぶ。確率的な多様化を目的にしない。",
      "criteria": {
        "guard_lantern": "定位置で灯籠を守り、鈴の方向も観察する",
        "inspect_bell": "実際に聞いた鳥居の鈴の地点を短く調べる",
        "wait_and_watch": "移動せず次の観測を待つ"
      }
    }
  }
}
```

この例は**形式と境界を示す架空の入力**。モデルID・言語・候補文は固定盤面の検証後に確定する。比較試験は`jev-latest`の可変エイリアスでなく固定したモデル版を使い、レスポンスの`model`も記録する。[公式モデル一覧](https://docs.typesafe.ai/models)は公開値が更新され得るため、実装・公開時に再確認する。[Choice仕様](https://docs.typesafe.ai/primitives/choice)では`choice`は最大確率の候補として返るが、これはゲーム側で確率抽選することではない。`confidence`を「正しく判断した確率」として扱わない。

### 応答の採用条件

1. 応答が`attempt_id`・`decision_id`に対応し、対象NPCが存在する。
2. 判断の`revision`が現行で、ゲーム内の待機期限内に届いた。ポーズ中の経過と再開後の期限の扱いは、同じゲーム内時計で一貫させる。
3. `choice`が送信時の候補にあり、今も合法で、対象地点に到達可能である。
4. 上を満たした場合だけ意図を採用し、**予兆→移動→結果の観測**へ進む。同じ`decision_id`を二度適用しない。

新しい足跡・盗難の証拠・見失い・調査結果などで`revision`を進める。狐の隠れた位置など狛犬が知らない世界変化でも、以前の意図が物理的に不可能になった時は応答を無効化してよい。ただし、その変化を新しい観測としてJevへ送らない。CP再挑戦は`attempt_id`を変え、未完了の判断をすべて破棄する。

**同じ状態の扱い:** 同じ試行内で性格版・行動傾向・観測・記憶・合法候補が変わらない再通知は新しい選択を求めず、現在の有効な意図を継続する。Jevの応答が反復時に揺れる可能性は固定盤面で測り、性格と手掛かりに反する揺れがあれば質問文・候補説明・モデル版を見直す。未検証のまま「同じ入力ならJevが必ず同じ返答をする」とは扱わない。

## 6. 障害時のローカル方針と復旧

| 条件 | その場の処理 | 復旧の条件 |
| --- | --- | --- |
| 応答待ち・一時的な遅延 | 狐の入力と描画を継続。狛犬は安全な直前の行動を短く続けるか、既知の手掛かりを見張る | 期限内の有効な応答だけ採用 |
| タイムアウト、通信断、形式不正、候補外、古い応答 | 応答を採用せずローカル方針。灯籠があると**知っている**なら守る。盗難を観測済みなら最後に見た証拠を調べる。何も知らなければ待機・巡視 | 新しい判断契機または再接続後に現行状態で再要求 |
| レート制限・過負荷 | 新規要求を無制限に連打しない。再試行は中継側で待機を増やす案 | APIとゲーム内期限を両方満たす時だけ採用 |
| 連続失敗が長い | 安全地点で中断・再接続を案内する案。無期限のローカル判断で完成版を進めない | [画面・操作仕様](ui-and-controls.md)の案内から接続を確認し、現行状態で判断を作り直す |

長時間切断の閾値、安全地点と復元位置はD-09の未決定事項。短い障害でも狛犬が突然停止・瞬間移動・理不尽な捕獲をしないことを優先する。APIの`429`・`529`に対するバックオフは[公式API仕様](https://docs.typesafe.ai/api)に従い、クライアントの待機期限との整合を検証する。`401`や`422`は設定・契約の失敗として記録し、同じ要求の高速再試行をしない。

## 7. CP再挑戦と記憶

**決定（D-18）:** CP-B／CP-Cへの再挑戦では、狛犬の観測・記憶を**そのCPの保存時点へ戻す**。灯籠、足跡、狛犬の位置・姿も一緒に復元し、失敗した挑戦の保留中の応答を破棄する。[基本設計](basic-design.md)の復元単位とそろえる。CP-Cは灯籠を盗む前の安全な境内入口で保存するため、S2から引き継いだ記憶は残り、その後に得た記憶は戻る。これにより、世界と記憶が一致した盤面から再挑戦できる。

同じ試行中に鈴の囮を二度使い、狛犬が最初の空振りを**実際に経験した**なら、その記憶は二度目の判断に残す。捕獲されてCPへ戻った後は、そのCP保存以降に得た空振り記憶を残さない（E-03、A-02）。プレイ後の「狛犬の記録」は追加候補。採用する場合は、実際の観測・採用意図・結果だけで組み立て、Jevが返していない内心の理由を書かない（A-06）。

## 8. 判断ログと固定盤面

| 記録するもの | 使い道 |
| --- | --- |
| `attempt_id`、`decision_id`、`revision`、場面・ゲーム内時刻 | 再挑戦、応答の重複・古さ、同じ盤面の再現 |
| 観測事実と由来、送信した候補ID・説明、性格と質問の版 | 観測外情報の混入、性格・候補文の変更を追う |
| 応答のモデル版、選択、遅延、`usage.input_tokens`、採用／破棄理由 | 性格・観測と選択の対応、遅延・利用量の評価。確率値は行動決定に使わない |
| 意図の実行結果、調査の空振り、捕獲理由、代替方針の発動 | 「なぜ動いたか」が実際の手掛かりで説明できるかを確かめる |

固定盤面は少なくとも、鈴だけ、足跡だけ、鈴と足跡の競合、同じ鈴の空振り後、盗難の証拠を見た後、狐が木陰にいて未観測、見失った後、巣で弟妹を見た時を用意する。最後の盤面ではJevの結末選択を呼ばないことを確認する。Jev版、同じ候補を使うローカル規則版、性格と対応する行動傾向だけを変えたJev版を比べる。性格だけを変える時は行動傾向も対応して更新し、観測・記憶は固定する。採用基準と件数は[検証計画](verification.md)で定める。

**秘密情報:** JevのAPIキーをゲーム配布物・リポジトリ・判断ログに含めない。中継先の配置と認証、利用枠の管理は[公開・運用設計](release-and-operations.md)で定める。実APIへの接続はまだ行っていない。
