# 『こぎつねと冬の灯り』設計ドキュメント一覧

> 2026-10-07 の実装進捗は [実装と検証の現在地](implementation-status.md) を参照。この一覧の「実装前」という記述は、設計文書を作成した時点の記録です。

版: 0.5／2026-10-04  
目的: **実装を始める前に何を決め、どの文書に記録するか**を明確にする。以下の文書はすべて草案を作成済み。草案の完成は仕様の最終確定や実装開始を意味しない。

## 作成方針

- このゲーム固有の判断に必要な文書だけを作る。既存の`research/`は根拠や案を集めた資料で、確定仕様は`design/`に置く。
- 各文書は「決定事項」「未決定事項」「判断の根拠」「確認方法」を区別する。後の変更では、関連する要件IDと影響する文書を記録する。
- ストーリーとゲームルールを先に決め、その上で画面・Jev・描画方式を具体化する。C++ + raylibや2.5Dは調査上の第一候補であり、境内1画面の検証まで確定扱いにしない。
- 文書がそろうことと実装開始は別。**制作コードの着手はユーザーの指示後**とする。
- 制作人数・完成時期・スケジュールはユーザーが設定する。この一覧には制作計画書を含めず、こちらから日程を提案・管理しない。

画風比較・モデル用設定画・背景・UIの一覧は[必要な画像一覧](image-reference-list.md)にまとめる。V-01の3枚を制作し、A「立体のある絵本映画」を採用した。新C-05の石像・変化・山犬の画像3枚も制作済みで、最終採用前。旧C-05の3案は不採用。

## 進める順番と設計の区切り

1. **要件定義:** `requirements.md`を確定する。完成版の範囲・主な対象OS・Jev接続方針・5〜10分以内の見せ場・GitHubでの公開内容は決定済み。
2. **ゲームの中身:** `game-design.md`と`story-and-levels.md`で、何が遊べて何が起こるかを決める。同時に`art-and-audio.md`で完成画面の基準を作る。
3. **基本設計:** `basic-design.md`で、画面と各システムの境界、状態の流れ、描画方式を決める。
4. **詳細設計:** `ui-and-controls.md`、`komainu-jev.md`、`technical-and-assets.md`で、操作・AI・素材工程を実装可能な粒度にする。
5. **検証と公開設計:** `verification.md`に合格基準と試作の順序をまとめる。Jevの理想的な判断を設計した後に使用量と費用を見積もる。`release-and-operations.md`で公開物と接続の条件を確定する。

**予定した10文書と判断記録の草案を作成済み。** 次は[判断記録](decision-log.md)の採用待ち案と要件の未決定事項をレビューし、実装の指示を受けた範囲で[検証計画](verification.md)の境内1画面から確かめる。守り手の新C-05画像は最終採用前。総プレイ時間と費用は理想の体験と実測を基に考える。制作人数・完成時期・スケジュールはユーザーが管理する。
