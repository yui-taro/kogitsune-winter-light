# 『こぎつねと冬の灯り』Jev の使い方と理由

作成日: 2026-10-18  
根拠: [狛犬・Jev仕様書](komainu-jev.md)、[判断記録](decision-log.md)、[Jev 自体の特徴](../research/jev-basics.md)、実装（[JevBridge.cpp](../game/src/JevBridge.cpp)、[relay.mjs](../server/relay.mjs)、[World.cpp](../game/src/World.cpp)）

## ひとことで

**Jev には、狛犬（守り手）が「次に何をするか」を一つ選ぶことだけを任せています。** 見える・聞こえるの判定、移動、捕まえる判定、物語の進行はすべてゲーム側のコードで決めます。

## 1. 仕組み（データの流れ）

```
狐が鈴を鳴らす・足跡を残す・灯籠を盗む…
        ↓
ゲーム（C++）：狛犬が実際に見た／聞いたことだけを「知識」として記録
        ↓  知識が意味のある形で変わった時だけ
ゲーム → 中継サーバー（relay.mjs）：知識と「今できる行動の候補」を送る
        ↓
中継サーバー → Jev：性格・観測した事実・候補を Choice の質問として送る
        ↓
Jev：候補から一つ選ぶ（例：inspect_bell）
        ↓
ゲーム：その答えがまだ有効か確かめてから実行（石から山犬に変わる→移動→また観測）
```

### 行動の候補（9 種類）

| 意図ID | 内容 |
| --- | --- |
| `guard_lantern` | 定位置で灯籠を守る（離れていれば戻って石になる） |
| `inspect_bell` | 聞いた鈴の場所を調べる |
| `inspect_tracks` | 見つけた足跡を追う |
| `inspect_last_seen` | 狐や灯籠の光を最後に見た場所を調べる |
| `watch_exit` | 森の分かれ道を見張る |
| `watch_torii_exit` | 境内西の鳥居側の出口を見張る |
| `watch_log_exit` | 境内東の倒木側の出口を見張る |
| `follow_visible_clue` | 今見えている狐や光を追う |
| `wait_and_watch` | その場で少し待って様子を見る |

### Jev に毎回送る性格

役目に忠実（灯籠を守る）、証拠を確かめてから動く、子狐を傷つけない、空振りの後は同じ囮に慎重になる。経験によって書き換えず、毎回同じ内容を送ります（`relay.mjs` の `character`）。

### 問い合わせるタイミング

毎秒は聞かず、狛犬の知識が変わった時だけ問い合わせます（`World.cpp` の `RecordObservation`）。

- 鈴を聞いた
- 新しい足跡を見つけた／調べ終えた
- 狐を見た／見失った
- 空の台座や運ばれる光を見た（盗まれたと知った）
- 調べに行ったが何もなかった

## 2. なぜこの使い方にしたのか

| 決めたこと | 理由 |
| --- | --- |
| **行動の「選択」だけを Jev に任せる** | Jev はもともと、用意した候補から判断を選ぶモデルで、文章は生成しません。距離の計算や何段階もの推論は苦手と公式に書かれているので、そこはコードで処理します。 |
| **狛犬が知っていることだけを送る**（狐の本当の位置は送らない） | 公平にするためです。プレイヤーが隠れたのに見抜かれる、という理不尽をなくします。中継サーバーでも、送る内容を作り直して余計な情報を落としています。 |
| **候補はゲームが「今できる行動」だけ用意する** | 鈴を聞いていないのに「鈴を調べる」は選べないようにして、おかしな行動を最初から防ぎます。どれが選ばれても、狐には逃げ道が残るように作っています。 |
| **確率から抽選せず、Jev が選んだ答えをそのまま使う**（D-17） | ランダムではなく「性格に合った一貫した行動」にするためです。 |
| **意味のある変化があった時だけ聞く**（D-17） | 費用と遅延を抑えるため、そして「鈴が鳴ったから振り向いた」のように理由がわかる動きにするためです。 |
| **ゲームは中継サーバーとだけ通信する**（PL-06） | API キーを配布物や GitHub に含めないためです（D-08 で GitHub 公開予定）。 |
| **古い答えや候補外の答えは捨てる** | 返事が届くまでの間に状況が変わることがあります。挑戦の ID・判断の ID・状態の版がすべて一致した時だけ答えを使います（`ApplyDecision`）。 |
| **失敗した時はローカルの代わりの判断に切り替える**（D-03） | Jev への接続は必須ですが、短い通信切れで狛犬が止まらないよう、同じ優先順位のルールで代わりに動かします（`LocalPersonalityPolicy`）。 |
| **モデルを `jev-1.13.0` に固定し、使用量を記録** | `jev-latest` は中身が変わることがあり、テスト結果を比べられなくなるためです。トークン数を記録して費用も追えるようにしています。 |
| **結末は Jev に選ばせない**（D-10） | 「弟妹を見た狛犬が火を分ける」という一つの結末を必ず見せるため、ゲームが決めます。 |

## 3. 遊んでいる時に見えること

- 鈴の囮を使うと、狛犬は耳と目線で反応し、離れると決めた時だけ山犬に変わって調べに行きます。
- 同じ囮で一度空振りすると、二度目はかかりにくくなります（空振りを記憶しているため）。
- 捕まって CP からやり直すと、狛犬の記憶もその CP の時点に戻ります（D-18）。
- 画面には判断のモードが表示されます：「Jev中継」「模擬応答」「代替判断」など。

## 4. 補足

- 設計書にある性格は「忠実・慎重・子への情」の 3 つですが、実装では「好奇心（証拠を確かめる）」を加えた 4 つになっています。
- 判断の質、応答の速さ、同じ入力でいつも同じ答えが返るかは、[検証計画](verification.md)でまだ測っていない項目です。
