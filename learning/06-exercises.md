# 6. 自分で変える練習

各練習は一度に一つだけ変更します。変更前に `make -C game test` を実行し、終わったらもう一度実行すると、どこで動作が変わったか分かります。最初は別の作業コピーで試すと戻しやすくなります。

## 練習 A: 走る速さを変える

**目的:** 入力、速度、テストのつながりを知る。

1. [World.cpp](../game/src/World.cpp) の `UpdateFox` で走行速度 `310.0f` を探す。
2. `280.0f` に変えて `make -C game test` を実行する。
3. 失敗したテストを読み、何がその速度を前提にしていたか調べる。
4. ゲームを起動して体感を比べ、元の数値へ戻す。

**自分への問い:** 移動速度を変えると、足跡の間隔と神社への到達時間はどう変わるか。固定フレーム数で経路を追うテストは、変更に強いか。

## 練習 B: 新しい観測を設計する

**目的:** 世界の事実と狛犬の知識を区別する。

紙の上だけで「灯籠が置かれた音を聞く」という観測を追加してみます。

1. `ObservationKind` と `Knowledge` に必要な値を考える。
2. どの条件でゲームが音を発生させるか、どの距離なら狛犬が聞くかを決める。
3. `LegalIntents` に新しい行動が本当に必要か考える。既存の `InspectLastSeen` などで足りるかもしれません。
4. 中継の `normalize` へ何を渡すか、候補外の返答をどう拒否するか書く。

**合格条件:** 狛犬が聞いていない遠方の置き音は Jev に送られない。聞こえた場所は子狐の現在位置として扱われない。

## 練習 C: CP-C の復元を説明する

**目的:** 通信中のやり直しを理解する。

`tests/test_contract.cpp` の `CheckpointRestoresWholeSnapshot` を使い、次の順序を図にしてください。

```text
鈴を観測 → CP-C 保存 → 子狐を発見 → 古い判断要求を送信
→ 灯籠を取る → 捕獲 → R → CP-C 復元 → 古い返答が到着
```

**合格条件:** 最後の返答がどの値の不一致で拒否されるか説明できる。

## 練習 D: 見た目だけを変える

**目的:** ゲーム規則と描画の分離を理解する。

`main.cpp` の `Glow` の半径だけを少し変え、ウィンドウで見比べます。`World.cpp` の `CanSeeFox` は変更しません。

**自分への問い:** 灯籠の見た目の明るさを変えても、狛犬の視認距離が変わらないのはなぜか。ゲームルールも変えるなら、どのテストを追加すべきか。

## 学習後に作る一枚の設計メモ

自分の言葉で次の四項目を各二、三文にまとめると、次の機能を追加するときの道しるべになります。

1. 入力が `WorldState` を変えるまで。
2. 狛犬の `Knowledge` が更新される条件。
3. Jev が選ぶ範囲と、ゲームが検査する範囲。
4. やり直し時に戻る値と、戻さず増やす ID。
