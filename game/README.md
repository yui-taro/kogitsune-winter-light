# こぎつねと冬の灯り — 実装版

実装の仕組みを順に学ぶ場合は [日本語の学習ノート](../learning/README.md) を参照してください。設計に対する到達点は [実装状況](../design/implementation-status.md) にまとめています。

設計書に沿って、巣 → 森 → 神社（鳥居と倒木の二経路）→ 灯籠を持つ帰路 → 巣の結末を遊べる実装です。描画は raylib 6.0、ゲーム状態は C++17、Jev への判断要求は別プロセスの中継で処理します。

起動すると、子狐と神社の灯籠を描いたタイトル画面が表示されます。「はじめる」をクリックするか、`Space`／`Enter` を押すと、約20秒のプロローグが始まります。子狐と弟妹の状況、神社の灯籠、狛犬を字幕と日本語音声で紹介します。物語の後は、移動・触れる操作と、伏せる・足跡を消す操作を描いた2枚の説明画面へ進みます。プロローグ中は `Enter` で次の場面へ進み、説明画面では `Enter` で次の説明／ゲーム開始へ進みます。`Space` で導入や説明を飛ばせます。画面右上の二つのボタンも同じ操作です。音声は物語の字幕と同じ文を macOS の Kyoko 音声で収録した Ogg ファイルで、Windows 版にも同梱されます。

BGMはタイトル、導入と寒い巣、森、神社、結末の5曲を場面に合わせて切り替えます。読み上げ中はBGMを小さくし、画面を離れたり一時停止したりすると再生も一時停止します。結末では、狛犬が火を見守る絵、灯籠を持って雪道を去る絵、暗い森の同じ巣で狐たちが安心して寄り添う絵を順に表示します。曲名・作曲者・配布元は [MUSIC-CREDITS.txt](assets/MUSIC-CREDITS.txt) に記載しています。配布元のゲーム利用条件に合わせ、BGMは単体の音源ファイルとして同梱せず、ゲーム用のパックからメモリ上で再生します。

## 操作

| 入力 | 行動 |
| --- | --- |
| `WASD` / 矢印 | 移動 |
| `C` / 左 Ctrl | 伏せる・解除 |
| 左 Shift | 走る・解除 |
| `Q` | 近くの足跡を尾で払う |
| `E` | 小枝・鈴・灯籠に触れる／灯籠を置く |
| 右下の四ボタン | 同じ四行動をマウスで操作 |
| `Esc` | 一時停止・再開 |
| `R` | 捕獲後の再挑戦／結末後にタイトルへ戻る |

巣では最初に小枝に触れ、左上の小道へ進みます。森の鳥居か右の倒木から神社に入り、社の前の唯一の灯籠を取ります。倒木の下を抜けるには伏せる必要があります。
灯籠を持って巣に帰った後も操作は続きます。森側の小道から巣の小枝まで歩き、小枝のそばで `E` を押して灯籠を置くと結末の演出が始まります。狛犬は灯籠の光をたどり、森の入口から歩いて現れます。
次に向かう小枝・灯籠・出口には、脈動する光と行き先の札が表示されます。小枝や灯籠に近づくと、札に `E` の操作が表示されます。倒木の札には伏せる操作も表示されます。
狛犬に見つかった時は、再挑戦の操作と、その場面に合わせた次の行動のヒントを表示します。
狛犬が判断して動く時は頭上に行動を表示し、歩行中は足元と体が動きます。石像の目も淡く光り、見張っていることが分かります。
狛犬は見つけた足跡を調べ終えると、その足跡を調査済みとして記憶します。新しい手掛かりがなければ元の立ち位置へ歩いて戻り、到着してから石像に戻ります。
灯籠をくわえて開けた道を進むと、狛犬は背後でも光に気づいて追いかけます。走っている間も見えている光の現在位置へ向かいます。森への帰り道では、通った出口側から遅れて現れます。伏せて茂みや倒木の陰に入ると光を見失い、最後に見た地点を調べます。
`C` は伏せる操作です。茂みの枠内または倒木の下に入ると隠れた状態になり、画面に「隠れ中」と表示され、灯籠の光の広がりも小さくなります。茂みの外で伏せているだけでは光は見えたままです。残した足跡は狛犬に調べられることがあります。

短く押した移動キーも受け付けます。`C` などを押して文字入力欄に文字が出る時は、キーボードの入力先がゲームではありません。ゲーム画面を一度クリックしてから操作してください。ゲームから別のアプリへ切り替えると進行は一時的に止まります。

## macOS でビルド

raylib 6.0 を `RAYLIB_DIR` の場所にビルドしてから、以下を実行します。既定値は `/private/tmp/jev-raylib-6.0` です。

```sh
make -C game RAYLIB_DIR=/path/to/raylib
make -C game test
make -C game bundle RAYLIB_DIR=/path/to/raylib
```

開発用実行ファイルは `game/build/foxgame`、配布しやすいアプリは `game/build/こぎつねと冬の灯り.app` です。Mac ビルドには Xcode Command Line Tools と libcurl が必要です。

## Windows でビルド

Visual Studio 2022、CMake 3.22 以降、vcpkg を使います。PowerShell でリポジトリのルートから:

```powershell
git clone https://github.com/microsoft/vcpkg.git vcpkg
.\vcpkg\bootstrap-vcpkg.bat -disableMetrics
.\vcpkg\vcpkg.exe install curl:x64-windows-static
cmake -S game -B game/build-windows -A x64 -DCMAKE_TOOLCHAIN_FILE="$PWD/vcpkg/scripts/buildsystems/vcpkg.cmake" -DVCPKG_TARGET_TRIPLET=x64-windows-static
cmake --build game/build-windows --config Release
ctest --test-dir game/build-windows -C Release --output-on-failure
```

CMake が raylib 6.0 を取得し、`Release/foxgame.exe` の隣へ `assets` をコピーします。実行時は exe と `assets` フォルダを一緒に置いてください。Windows 実機での動作確認と配布パッケージの署名は、まだ完了していません。

## Jev 中継

ゲームに API キーを埋め込みません。リポジトリ直下の `.env`（Git 管理対象外）に `TYPESAFE_API_KEY=取得したキー` を設定し、Node.js 20 以降で中継を起動します。値に `Bearer ` は付けません。開発中は中継を `127.0.0.1:8787` に限定しています。

```sh
node --env-file=.env server/relay.mjs
JEV_RELAY_URL=http://127.0.0.1:8787/decision game/build/foxgame
```

API キーなしで通信を試す場合は `JEV_MOCK=1 node server/relay.mjs` を使います。画面右上の表示は、未設定なら「ローカル試作」、初回返答前は「応答確認中」、成功後は「Jev中継」または「模擬応答」、失敗時は「代替判断」です。通信が失敗しても、狛犬は観測に基づくローカル判断で動きます。2026年10月18日に実 API から正常応答を確認しました。

実際の Jev 呼び出しには TypeSafe の Choice を使い、返答の `choice` だけを採用します。`probabilities` は抽選に使いません。中継へは狛犬の姿と位置、直前の行動、鈴の回数、手掛かりの古さ、見聞きした事実を渡します。狐の真の位置や鈴が鳴った理由は渡しません。ゲーム側は試行 ID・判断 ID・改訂番号・合法候補を検査して古い返答を破棄します。追跡中は最新の目撃地点へ進みますが、目撃地点が少し動くたびには再問い合わせしません。短い見張りは時間が来ると再判断し、鈴が再び鳴った時も新たに判断します。

ブラウザ版で Jev を使う場合は、中継をネット上（Render）に置き、公開ページのログインを通して接続します。手順は [server/HOSTING.md](../server/HOSTING.md) を参照してください。

中継は既定で固定版 `jev-1.13.0` を使います（`JEV_MODEL` で変更可）。実 API の応答ごとに、応答したモデルと入力トークン数を標準出力へ `{"event":"jev_usage","model":...,"inputTokens":...}` の形で1行記録します。

## 検証

```sh
make -C game test build/test_bridge
cd server && node --test test.mjs
```

最後のテストはローカルポートを使い、模擬中継と C++ クライアントを実際に HTTP で接続します。模擬 Jev を相手に 429/529・形式不正・候補外の応答も確認します。ゲームの状態テストは、観測の境界、候補外の拒否、古い返答、捕獲後の記憶復元、神社の右経路、全場面の結末到達を確認します。GitHub Actions の `Tests` ワークフローが push と PR で同じテストを Ubuntu と macOS で実行します。

実際のJev APIを使う固定盤面試験は、`node --env-file=.env server/live-smoke.mjs` で実行します。最大9件の判断を現行の中継経由で送り、候補・遅延・入力トークン数を表示します。認証や通信が失敗した場合は最初の失敗で止まります。まず `node server/live-smoke.mjs --dry-run` で入力の形式だけ確認できます。比較対象のモデルを指定する場合は `JEV_MODEL=jev-1.14.0` を付けます。キーや判断要求の本文は出力しません。

どのテストが設計書の要件 ID・検証ゲート・固定盤面に対応し、何が手動・実機・実API での確認待ちかは [テスト対応表](../tests/README.md) にまとめています。自動テストの通過だけでは公開品質の合格になりません。

## 素材と現状

画面は固定背景と透過スプライトの 2.5D 試作です。子狐の通常歩行・走り・伏せ歩きに、それぞれ横・斜め前・正面・斜め後ろ・背面の4コマを用意しました。左右反転を合わせて8方向、合計60コマ分の画像を使います。コマは実際に進んだ距離で切り替え、立ち止まると止まります。元画像は `art-source`、ゲーム用に足元を揃えた画像は `assets` にあり、`tools/prepare_fox_animation.py` で再生成できます。効果音は実行時に合成します。フォントのライセンスは `assets/OFL.txt`、JSON と raylib のライセンスは `vendor` にあります。公開時の中継先・利用者認証・費用上限は未決定です。
